Activation and credentials

Loading integrations…

You own each integration’s on/off switch and its credentials. Secret values are encrypted at rest and only a masked hint is shown; saving a value also writes the matching *_OVERRIDE field in server/.env. A value you add or replace is sent to its provider for a live check first — a key the provider rejects is never saved, and the reason appears under the field. An integration can only be turned on when its required credentials are present. Adding, replacing or clearing a credential also asks for the current 6-digit code from your authenticator app — pair one on the Security page first.

Restore defaults

Clear every API key saved here and return each integration to the original server/.env values and default on/off state. The *_OVERRIDE values are deleted, so the original keys apply again.
